# mem-ai

Standalone synchronous Rust library for consent-gated storage advice. Add a path dependency on this directory and use `discover()` and `advice("claude", &summary, consent)`.

`ScanSummary` contains numeric totals and up to four nonduplicated category aggregates (`cache`, `build`, `downloads`, `other`). No paths, names, file content, arbitrary labels or prompt strings are accepted. Serde rejects unknown fields. Category sums must fit the total. Require explicit per-request UI consent before passing `true`. Discovery never performs inference.

Discovery separates `installed` from `usable`. Claude supports the reviewed `2.1` patch contract starting at `2.1.296 (Claude Code)`, with canonical version output, every required isolation flag and its documented help semantics, and an existing first-party subscription reported by `auth status --json`. New major/minor contracts, older patches and prerelease/malformed versions fail closed. Patch compatibility alone never suffices: every invocation rechecks discovery and validates its actual startup stream. The `2.1.299` update was verified with real subscription fixture inference through the production bridge. Discovery performs no inference and reports readiness, not prior runtime attestation. Reasons distinguish missing/failed/timed-out CLI probes, unsupported versions, missing flags/semantics, auth probe errors, unverified login and unsupported billing. Codex, agy, OpenCode, pi and Ollama remain unavailable until a separately reviewed tool-free adapter exists; their login is not asserted either way. Installed means the version probe succeeds, not that a file was found.

Claude launches in a fresh empty temporary directory with a cleared environment, retaining only PATH, HOME, CLAUDE_CONFIG_DIR, XDG_CONFIG_HOME, XDG_CACHE_HOME, TMPDIR and TLS certificate paths. API keys and other CLI configuration environment variables are not forwarded. The CLI itself may read its existing OAuth credentials; this library never reads credential files or extracts tokens. It does not use `--bare`, which disables OAuth login. No API-key provider or fallback is supported.

Isolation uses `--tools ""`, `--safe-mode`, `--restricted`, `--strict-mcp-config --mcp-config '{"mcpServers":{}}'`, `--disable-slash-commands`, `--no-chrome`, `--setting-sources ""`, `--settings` with `disableAllHooks: true` and explicit `false` overrides for `cc-plugin-agents-md@builtin`, `cc-plugin-telemetry@builtin`, and `cc-plugin-plugin-authoring@builtin`, `--no-session-persistence`, and a replacement system prompt. Read-only sandboxing alone is insufficient and is never used as the guarantee. Safe mode alone leaves builtin plugins enabled; the explicit overrides were verified against real startup events. Safe mode disables customizations, restricted mode ignores ordinary settings, and explicit tools/MCP controls remove model capabilities. The stream is checked as it arrives, and unsafe initialization terminates the CLI without waiting for a model result. Initialization must confirm empty tools, MCP servers and plugins. Tool-use blocks, unexpected event types, events after the result, provider errors, malformed output and missing initialization are rejected. Numeric input is supplied before the CLI emits initialization; runtime checks govern accepting the output and aborting unsafe execution, not pre-transmission attestation. Managed organizational policy and the installed CLI remain part of the trust boundary; this is capability isolation, not OS process isolation or a defense against a malicious replacement executable.

Advice is untrusted plain text. Render it as escaped text, never HTML, shell commands or deletion instructions. Only manual review is suggested; downstream callers must never automatically execute model text. Aggregates can still be sensitive: consent permits transmission to the chosen provider. Numeric aggregates do not establish whether files are safe to delete. Usable means compatible local flags and subscription login, with runtime capability checks required on each request, not guaranteed quota or network availability. Account billing/extra-usage controls remain the account owner's responsibility; this crate does not opt into paid usage or change account settings.

Probes have an 8-second deadline, inference a 90-second deadline, output a 64 KiB cap, and advice a 16 KiB cap. Errors contain no provider stderr or account metadata. A valid terminal provider error is distinguished from malformed/unsafe runtime output. When a post-initialization `rate_limit_event` reports `rate_limit_info.status=rejected` and the terminal result reports `is_error=true`, return a fixed usage-limit reason for the recognized five-hour, weekly, weekly Opus or weekly Sonnet window. Unrecognized windows use a generic limit reason; allowed/warning/unknown statuses clear stale quota evidence, and a successful result is never replaced by a quota error. Raw result/error text, account identifiers and reset metadata are never echoed. Other terminal errors retain a generic provider-error reason. Discovery cannot guarantee quota, network or account availability. Selecting another existing authorized CLI config with `CLAUDE_CONFIG_DIR` is an explicit caller choice; the app never switches accounts, changes credentials or opts into paid fallback. The synchronous API should run off the UI thread. It does not currently expose cancellation or terminate descendant process groups; models have no process-launch tools. Trust PATH and the installed CLI, and rerun verification after updates.

```sh
cargo test --manifest-path crates/mem-ai/Cargo.toml
cargo fmt --manifest-path crates/mem-ai/Cargo.toml --check
cargo clippy --manifest-path crates/mem-ai/Cargo.toml --all-targets -- -D warnings
cargo run --manifest-path crates/mem-ai/Cargo.toml --example verify
# Explicitly authorized fabricated-summary inference, using existing subscription:
cargo run --manifest-path crates/mem-ai/Cargo.toml --example verify -- --infer-with-consent
```

Fixture tests never invoke an actual model. The verification example sends only fabricated totals when its explicit consent argument is supplied.
